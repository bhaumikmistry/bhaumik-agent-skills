# Review mode

Review a message the user has written (or is about to send) against the communication principles.

## Flow

### Step 1: Read the message

The user will either paste a message or reference one. Read it carefully.

### Step 2: Score against principles

For each of the 5 principles, assess:
- **Pass** — principle is respected or not applicable
- **Flag** — something could land poorly

Only flag things that matter. Not every message needs all 5 principles. A quick "thanks, done!" doesn't need coaching.

### Step 3: Check anti-patterns

Scan for specific anti-patterns from principles.md. If present, name the pattern and explain how it might land.

### Step 4: Check positive patterns

If good patterns are present, call them out briefly. Reinforcement matters as much as correction.

### Step 5: Provide rewrites

For each flagged item:
1. Quote the problematic text
2. Explain how it might land (1 sentence)
3. Offer a specific rewrite

Format:
```
**Flag:** "I wonder why this is still routing to FAR"
**Lands as:** "Someone should have caught this" — questioning rather than observing
**Rewrite:** "Looks like this is still routing to FAR — might be a leftover from the transition"
```

### Step 6: Overall assessment

End with one of:
- "This is clean — send it." (if no flags)
- "One tweak and it's good." (if minor)
- "The core message is right, but the framing needs work." (if structural)

## Calibration

- A message to a peer can be more direct than one to a junior
- Technical disagreement is fine — dismissal of concerns is not
- Urgency is fine — steamrolling is not
- Short messages get less scrutiny — don't over-coach a 5-word reply

## What NOT to do

- Don't make the user feel bad about their draft — they're asking for help, not judgment
- Don't turn every message into a therapy session
- Don't add softeners that dilute the message's point
- Don't flag things that are fine just because you can
