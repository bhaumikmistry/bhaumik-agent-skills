# Draft mode

Help the user write a message with the communication principles applied.

## Flow

### Step 1: Gather context

Ask (one at a time, not all at once):
1. Who is the recipient? (name, role, seniority relative to user)
2. What's the context? (what happened, what prompted this message)
3. What's the goal? (inform, ask for help, give feedback, coordinate, escalate)

If the user provides all of this upfront, skip to Step 2.

### Step 2: Identify risk factors

Based on context, check:
- Is recipient junior? → Apply maximum care (principle 5 especially)
- Is there a disagreement? → Apply principles 2, 3, 4
- Is user under stress/deadline pressure? → Flag tendency to provide answers before asking
- Is this a group message with CCs? → Check if CCs need to be there

### Step 3: Draft the message

Write the message applying all 5 principles. Specifically:
- Lead with context if recipient might lack it (principle 1)
- If there's disagreement, name it directly rather than implying (principle 2)
- Include a question that surfaces their constraints (principle 3)
- Keep scope narrow — don't relitigate adjacent topics (principle 4)
- Frame recommendations as your reasoning journey, not conclusions (principle 5)

### Step 4: Self-review

Before presenting the draft, check it against the anti-patterns list in principles.md. If any are present, fix them.

### Step 5: Present with callouts

Show the draft and briefly note:
- What principles were applied and where
- Any adjustments made from what the user might have written naturally
- Why specific word choices matter for how it lands

Keep callouts short — 1-2 sentences per adjustment, not a lecture.

### Step 6: Iterate

If the user wants changes, apply them while preserving the principles. If a requested change reintroduces an anti-pattern, flag it gently: "That version works — one thing to watch: the 'I wonder why' framing can read as questioning rather than observing. Want to keep it or swap to 'Looks like X is still happening'?"

## What NOT to do

- Don't moralize or lecture about being nice
- Don't refuse to write direct/assertive messages — directness is fine, dismissiveness is not
- Don't add unnecessary softeners that make the message wishy-washy
- Don't over-explain the coaching — the user asked for a draft, not a lesson
- Don't change the user's voice — adjust patterns, preserve personality
